# 三种创建的方式，在实际部署时它封装好的库是直接创建模型吗？

> 结论先说：**是**。`nn.Sequential`、`nn.Module` 子类、函数式三种写法，编译/导出后拿到的是同一个东西——
> 一张算子图 + 一组权重。部署时（ONNX/TensorRT/RKNN/LibTorch）调用的 `create/load` 就是在重建这张图并灌权重，
> 跟你当初用哪种写法描述它没有关系。

## 1. 三种写法对照

```python
import torch.nn as nn

# 写法一：Sequential（顺序堆叠，无分支）
model_a = nn.Sequential(
    nn.Conv2d(3, 32, 3, padding=1),
    nn.ReLU(),
    nn.MaxPool2d(2),
)

# 写法二：继承 nn.Module（有分支/复用/自定义 forward 时必须用）
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = nn.Conv2d(3, 32, 3, padding=1)
        self.act = nn.ReLU()
    def forward(self, x):
        return self.act(self.conv(x))
model_b = Net()

# 写法三：函数式（无状态，参数/权重需自己管理）
import torch.nn.functional as F
def forward_fn(x, w, b):
    return F.relu(F.conv2d(x, w, b, padding=1))
```

## 2. 为什么导出后没区别

`torch.onnx.export` / `torch.jit.trace` 是对**输入跑一遍 forward**、记录实际执行的算子：

```python
torch.onnx.export(model_b, torch.randn(1, 3, 224, 224), "net.onnx",
                  input_names=["input"], output_names=["output"],
                  opset_version=12, dynamic_axes={"input": {0: "batch"}})
```

所以：

- 三种写法导出的 ONNX 图**完全一致**（前提是 forward 里的实际计算一样）。
- `Sequential` 只是省了写 `forward`，本质还是 `nn.Module`。
- 函数式写法如果直接导出会缺权重（权重是外部传入的），所以部署前通常也要包一层 `nn.Module`。

## 3. 部署端拿到的到底是什么

| 部署方式 | 拿到的东西 | “创建模型”的含义 |
| --- | --- | --- |
| LibTorch (.pt) | TorchScript 图 + 权重 | `torch::jit::load()` 反序列化 |
| ONNX Runtime | ONNX 图 + 初始值 | `InferenceSession("net.onnx")` |
| TensorRT | 序列化的 engine | `deserializeCudaEngine()` |
| RKNN | `.rknn` 模型 | `rknn_init()` 加载 |
| TFLite / AIMO | `.tflite` 或转换后模型 | `Interpreter` + `AllocateTensors` |

这些库都**不需要**你的 Python 类定义，它们只认图结构和权重。所以“封装好的库是不是直接创建模型”——是的，
它按图重建执行计划，不会调用你写的 `Net.__init__()`。

## 4. 真正影响部署的差异在这里

1. **动态结构**：forward 里有 `if` 依赖输入值（数据相关分支）→ 导出只能固化一条路径，或需要 `torch.jit.script`。
2. **自定义算子**：用了部署端不支持的 op → 导出失败或退化为 CPU 子图。
3. **后处理**：NMS、解码框这些千万别放在模型里（导出麻烦），放到 C++/Python 侧手写。
4. **输入输出格式**：导出时用 `dynamic_axes` 声明 batch，否则部署时只能喂固定 batch。

## 5. 实践建议

- 训练用写法二（`nn.Module`），最灵活。
- 结构简单、纯顺序的推理模块用写法一，代码短。
- 部署前统一走：`torch.jit.trace` 自检 → 导出 ONNX → `onnxsim` 简化 → 目标平台转换。
