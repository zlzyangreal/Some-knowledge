# 远程服务一直在下载服务器

> 现象：VS Code 远程连接卡在 “Downloading VS Code Server” / “Setting up SSH Host”，一直转圈或反复重试。

## 原因

VS Code 连上远端后，要在远端 `~/.vscode-server/bin/<commit-id>/` 下装一个同版本的 server。
这个下载走的是远端机器的网络（不是本机），远端没外网、被墙、磁盘满、或残留了坏掉的半成品都会卡住。

## 排查顺序

```bash
# 1. 看远端到底有没有在写
ssh user@host
ls -la ~/.vscode-server/bin/          # 有目录但里面只有 .tar.gz 或 tmp，就是下载失败
df -h ~                                # 磁盘满也会卡住
```

2. 在**远端**测试能不能访问下载地址：

```bash
curl -I https://update.code.visualstudio.com/commit:<commit-id>/server-linux-x64/stable
```

拿不到 200 就是网络问题。

## 解决办法

### 方案 A：本地下载，手动上传（最稳）

```bash
# 版本号看本机 VS Code：帮助 → 关于 → Commit
# 在能上网的机器下载
wget https://update.code.visualstudio.com/commit:<commit-id>/server-linux-x64/stable -O vscode-server.tar.gz

# 上传并解压到远端对应目录
ssh user@host "mkdir -p ~/.vscode-server/bin/<commit-id>"
scp vscode-server.tar.gz user@host:~/.vscode-server/bin/<commit-id>/
ssh user@host "cd ~/.vscode-server/bin/<commit-id> && tar -xzf vscode-server.tar.gz --strip-components=1 && rm vscode-server.tar.gz"
```

### 方案 B：清掉残留重来

```bash
rm -rf ~/.vscode-server          # 会删掉所有扩展与历史，但最干净
```

### 方案 C：换国内镜像

```bash
# 远端 shell 里设置（写进 ~/.bashrc 更省事）
export VSCODE_SERVER_DOWNLOAD_URL=https://vscode.cdn.azure.cn
```

### 方案 D：远端离线安装扩展

```bash
code --install-extension xxx.vsix --extensions-dir ~/.vscode-server/extensions
```

## 常见坑

- 远端用户没有写 `~` 的权限 → 换一个有权限的用户，或用 `--server-data-dir`。
- 远端 glibc 太老（CentOS 7）→ 需要 VS Code 1.85 或更早版本，新版本要求 glibc ≥ 2.28。
- 反复重连又多份残留 → 每次失败先 `rm -rf ~/.vscode-server/bin/<commit-id>`。
- 公司内网有代理 → 远端也要配 `http_proxy`，或在设置里填 `remote.SSH.useLocalServer`。
