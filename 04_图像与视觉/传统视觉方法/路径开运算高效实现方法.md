# 1. 核心概念：什么是“路径开运算”？
“路径”与传统形态学的区别
## 1.1 为什么要提出这个概念？
传统的形态学开运算（Opening）通常使用两种结构元（Structuring Elements, SE）：
- **直线段 (Line Segments)：** 只能保留完美的直线。如果物体稍微弯曲，就会被过滤掉 。
- **连通区域 (Connected Areas)：** 基于像素数量（面积）。它无法区分“圆形的斑点”和“细长的线条”，只要面积够大都会被保留 。
**路径开运算 (Path Opening)** 的目的就是填补这两者之间的空白：它能提取**细长的**、**有方向的**，但**允许一定程度弯曲**的结构 。
## 1.2 定义路径与邻接图
路径开运算是建立在**邻接图 (Adjacency Graph)** 之上的。
- **有向图：** 图像中的每个像素是一个节点。像素之间的连接关系（边）决定了路径可以怎么走
- **方向约束：** 作者通过设计特定的邻接图来限制路径的方向。
	- 例如，Fig. 2(b) 展示了一个“南北向 (S-N)”的邻接图。在这个图中，一个像素只能连接到它上方三个相邻的像素（左上、正上、右上）。
	- 这意味着，在这个图中定义的“路径”，本质上被限制在一个 **90度角的圆锥体** 内 。它大体是向上的，但可以在这个锥体范围内左右摆动。
![[路径开运算优化1.png]]
- **路径开运算 $\alpha_L(X)$：** 对于二值图像 $X$，路径开运算的结果是保留所有属于长度至少为 $L$ 的路径的像素集合 7。简单来说，如果一条弯弯曲曲的线长度超过 $L$ 且符合邻接图的走向，它就被保留；否则被剔除。
# 2. 基础算法：递归计算路径长度
一种基于**动态规划（Dynamic Programming）的图像扫描算法**。这里的“递归”并非指编程中的函数递归调用，而是指**数学上的递归定义**：一个像素的状态值依赖于其前驱邻域像素的状态值。
## 2.1 核心目标：路径分解
在计算穿过像素 $p$ 的最长路径长度 $\lambda[p]$ 时，直接搜索整条路径是非常低效的。算法将路径长度分解为两个独立的方向分量：
1. **$\lambda^-[p]$（前向路径长度）：** 仅计算以像素 $p$ 为终点，从单一方向（例如“上方”）汇聚到 $p$ 的最长路径长度（不包含 $p$ 自身）。
2. **$\lambda^+[p]$（后向路径长度）：** 仅计算以像素 $p$ 为起点，向相反方向（例如“下方”）延伸的最长路径长度（不包含 $p$ 自身）。
3. **总长度：** $\lambda[p] = \lambda^-[p] + \lambda^+[p] + 1$。
这种分解使得我们可以通过两次不同方向的线性扫描来完成计算。
## 2.2 邻接关系与依赖性
算法必须预先定义一个**邻接图（Adjacency Graph）**。以论文重点讨论的 **S-N（南-北）90° 图** 为例 ：
![[路径开运算优化2.png]]
- **方向约束：** 路径被限制在垂直方向的 90 度圆锥内。
- **像素依赖：** 对于任何一个像素 $p=(x, y)$，其路径连通性仅取决于其上一行（$y-1$）的三个邻居：左上 $(x-1, y-1)$、正上 $(x, y-1)$ 和右上 $(x+1, y-1)$。
这种局部依赖性是算法能够高效执行的基础。
## 2.3 递归定义（状态转移方程）
根据论文公式 (2) 和 (3)，我们可以写出严谨的状态转移逻辑。
### 2.3.1 向上路径 $\lambda^-$ 的计算
![[路径开运算优化3.png]]
对于图像中的每个像素 $p$，其 $\lambda^-[p]$ 值由以下规则决定 ：
1. **如果 $p$ 是背景像素（值=False）：** 路径在此中断，$\lambda^-[p] = 0$。
2. **如果 $p$ 是前景像素（值=True）：** $\lambda^-[p]$ 等于其所有**前驱邻居（Predecessors) 中**路径长度的最大值加 1。
$$\lambda^-[p] = 1 + \max \left( \lambda^-[\text{左上}], \lambda^-[\text{正上}], \lambda^-[\text{右上}] \right)$$
### 2.3.2 向下路径 $\lambda^+$ 的计算
![[路径开运算优化4.png]]
逻辑完全对称，但依赖方向相反。$\lambda^+[p]$ 取决于其**后继邻居（Successors）**（即下一行的三个邻居）的最大值 。
## 2.4 算法执行流程：光栅扫描
由于每个像素的值仅依赖于其“上一行”或“下一行”的邻居，因此不需要随机访问，只需进行有序扫描：
### 2.4.1 **正向扫描：**
1. 从图像的第一行扫描到最后一行。
2. 计算每一行像素的 $\lambda^-$ 值。由于计算当前行时，上一行的 $\lambda^-$ 值已经计算完毕并存储，因此可以直接调用。
 _结果：_ 扫描结束后，内存中存储了整张图的 $\lambda^-$ 矩阵。
### 2.4.2 **反向扫描：**
1. 从图像的最后一行扫描到第一行。
2. 计算每一行像素的 $\lambda^+$ 值。同样，下一行的 $\lambda^+$ 值已知。
在此过程中，通常会直接读取之前算好的 $\lambda^-$，计算总长度 $\lambda[p] = \lambda^- + \lambda^+ + 1$，并判断是否保留该像素（即是否 $\ge L$）。
# 3. 核心贡献：高效的“有序”算法
如果直接对灰度图像的每一个灰度级都进行上述递归计算，效率并不高。本文的核心贡献在于提出了一种**有序更新机制**，大大降低了复杂度。
## 3.1 阈值分解与增量更新
灰度形态学可以通过**阈值分解**来实现：将灰度图视为一系列堆叠的二值图（从高亮到暗）。
- **关键观察：** 当阈值 $t$ 变化到 $t-1$ 时，二值图像的变化通常很小（只有一部分像素从“前景”变成了“背景”，或者反之）。
- **策略：** 只要我们知道阈值 $t$ 时的路径长度信息，计算 $t-1$ 时，不需要重算整张图，只需要更新那些**状态发生改变的像素**及其受影响的邻域 。
# 4. 算法流程
## 4.1 **初始化与排序：**
1. 将所有像素按照灰度值（强度）进行**排序** 。这是为了快速确定在每个阈值下哪些像素会发生变化。
2. 初始化所有像素为“开启”状态（假设从最低阈值开始），并计算初始的路径长度 $\lambda^-$ 和 $\lambda^+$ 。
## 4.2 **遍历阈值 ：**
1.  按照灰度级顺序遍历。对于每一个新的阈值，找出那些灰度值低于当前阈值的像素（即在这个阈值下变成“背景/False”的像素）。
2.  将这些像素标记为**活跃 (Active)** 并放入队列 。
## 4.3  **队列传播更新：**
- 利用队列系统（FIFO），只处理活跃像素。
- **更新 $\lambda^-$：** 从上到下扫描受影响的行。如果一个像素变成 False，它的 $\lambda^-$ 归零。如果它的 $\lambda^-$ 变了，那么依赖它的（下方的）像素也可能需要更新，于是将这些邻居加入队列 。
- **更新 $\lambda^+$：** 类似地，从下到上扫描，更新向下延伸的路径长度。
## 4.4 **判定与修剪：**
- 如果在当前阈值下，某像素的总路径长度 $\lambda[p]$ 变得小于设定的参数 $L$，则该像素在最终结果中被移除（即该像素在这个灰度级被“开运算”掉了）19。
- **长度启发式优化 (Length Heuristic)：** 如果某像素的最大路径长度已经小于 $L$，它在后续更高的阈值下也不可能构成长度为 $L$ 的路径。因此可以永久将其标记为 False，不再参与后续计算。这极大地加速了算法 。
# 5. 扩展一：开运算变换
除了输出滤波后的图像，该算法还可以生成“开运算变换图”。
- **定义：** 对于每个像素，不只是判断它是否保留，而是记录穿过它的**最长路径的长度** 。
- **实现：** 在上述有序算法的运行过程中，利用一个链表（Linked List）存储每个像素在不同阈值下的路径长度变化点 $(t, \lambda[p])$ 。
- **用途：** 这个压缩的数据结构可以在后续极快地查询任意长度 $L$ 的开运算结果，或者用于生成粒度分布曲线（Granulometry）。
# 6. 扩展二：不完整路径
为了解决噪声导致路径断裂的问题，作者引入了“不完整路径”概念。
## 6.1 问题背景
标准的路径开运算要求路径必须连续。如果一条长线中间断了一个像素（噪声），整条线可能就因为长度不足 $L$ 而被丢弃 。
## 6.2 解决方案：允许“跳跃”
- **定义：** 允许路径中存在最多 $K$ 个缺失像素（Gaps）。
- **状态升级：** 算法的状态不再只是存储一个长度值 $\lambda[p]$，而是存储一个**数组** $\lambda[p, k]$。
    - $\lambda[p, k]$ 表示以像素 $p$ 为起点，且路径中包含 $k$ 个缺口时的最长路径长度 。
- **更新规则变更：**
    - 在计算路径长度时，如果在像素 $p$ 处断开了（$b[p]=false$），我们不再直接归零，而是继承邻居“$k-1$ 个缺口”的路径长度，并给予一定的惩罚 。
    - 公式变为：$\lambda^-[p, k] = 1 + \max(\text{neighbors with } k \text{ or } k-1 \text{ gaps})$ 。
## 6.3 复杂度代价
这种改进赋予了算法类似 Rank-Max 滤波器的抗噪能力 ，但代价是内存和计算量随 $K$ 线性增加（需要维护 $K$ 个状态）。即便如此，相比之前的递归实现，这种有序更新方法在速度上仍有显著提升（快 4-80 倍）。
