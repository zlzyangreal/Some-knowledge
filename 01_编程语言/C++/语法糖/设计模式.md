## 1. 三类模式速记

| 类别 | 解决什么 | 典型模式 |
| --- | --- | --- |
| 创建型 | 对象怎么造 | 单例、工厂、建造者 |
| 结构型 | 类/对象怎么组合 | 适配器、装饰器、代理、组合 |
| 行为型 | 对象之间怎么通信 | 观察者、策略、命令、状态机 |

## 2. 适配器（Adapter）——上面那篇博文的主题

把一个类的接口“翻译”成调用方期望的接口，让原本不兼容的两个类能一起工作。

```cpp
// 旧接口：只有 220V
class Socket220V {
public:
    int output220() { return 220; }
};

// 新需求：要 5V
class Target5V {
public:
    virtual int output5() = 0;
    virtual ~Target5V() = default;
};

// 适配器：继承目标接口，内部持有旧对象
class ChargerAdapter : public Target5V {
public:
    explicit ChargerAdapter(Socket220V* s) : socket_(s) {}
    int output5() override { return socket_->output220() / 44; }
private:
    Socket220V* socket_;
};
```

对比记忆：

- **适配器**：接口转换，语义不变（220V → 5V，还是供电）。
- **装饰器**：接口不变，功能叠加（给 Stream 加上缓冲、加密）。
- **代理**：接口不变，控制访问（懒加载、权限、远程调用）。

## 3. 单例

见 [[设计模式单例模式]]。核心是“私有构造 + 静态局部变量”（C++11 起线程安全）：

```cpp
class Singleton {
public:
    static Singleton& instance() {
        static Singleton inst;   // C++11 保证线程安全且只初始化一次
        return inst;
    }
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
private:
    Singleton() = default;
};
```

## 4. 该不该用

设计模式是“补丁”，不是“目标”。如果一个模式用上去让代码更长、更难懂，说明当前场景不需要它。
C++11 以后很多模式被语言特性吸收：单例 → `static` 局部变量；策略 → `std::function` + lambda；
工厂 → 模板或 `std::variant`。
